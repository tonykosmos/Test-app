# Data Model: Visited Places Map

Types shared by both apps live in `packages/shared`. Persistence uses the tables below. Column names are snake_case in PostgreSQL. `synchronize` stays off; these tables are created by one migration that also inserts the demo traveler.

## Traveler

A person who owns places. This version has exactly one row.

| Field | Required | Rules |
| --- | --- | --- |
| id | yes | UUID. The demo row is `00000000-0000-4000-8000-000000000001`. |
| display_name | yes | "Demo" for the seeded row. |
| created_at | yes | Set when the row is inserted. |

Relationships: a traveler has many visited places. The application does not expose create, update, or delete for travelers.

## Visited Place

One pinned location.

| Field | Required | Rules |
| --- | --- | --- |
| id | yes | UUID generated by the server. |
| traveler_id | yes | Foreign key to traveler. Always the demo traveler in this version. Deleting a traveler is not supported here, so the database restricts deleting a traveler who still has places. |
| title | yes | 1 to 100 characters after trimming. Blank is rejected. |
| description | no | At most 1,000 characters. Empty becomes null. |
| latitude | yes | -90 through 90. |
| longitude | yes | -180 through 180. |
| place_name | no | Name returned by search or reverse lookup. Empty when the location is unnamed. |
| city | no | Mapbox `context.place.name` when present. |
| country | no | Mapbox `context.country.name` when present. |
| visited_on | no | Calendar date. Absent when the traveler gives no date. |
| visited_on_precision | conditional | `day`, `month`, or `year` when `visited_on` is set. Null when `visited_on` is null. The two fields are either both set or both null. |
| created_at | yes | Server time when the place is created. |
| updated_at | yes | Server time on every successful edit. |

A month-precision date is stored as the first day of that month. A year-precision date is stored as 1 January of that year. Clients display the precision, not the stored first day.

Validation:

- A full date, month, or year in the future is rejected. "Future" is based on the current UTC date.
- Coordinates come from a chosen search result or from a map click. The client does not invent a third source.
- Two places may share the same coordinates. That is a repeat visit, not an update.

Relationships: many places belong to one traveler. Nothing else references a place in this version.

## State changes

A place has no status field. It is created, replaced in full by an edit, or deleted.

- **Create**: title and coordinates are required. Description, place name, city, country, and visit date are optional.
- **Edit**: the traveler may change every field, including coordinates. The id, traveler, and created time stay the same.
- **Delete**: confirmation happens in the interface. The server then removes the row. There is no archive.

## Sorting

The list and the default API order are `visited_on` descending, undated places last, then `created_at` descending so two visits on the same date stay stable.
